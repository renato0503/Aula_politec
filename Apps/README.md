## Andamento (30/10/2026)

Os 20 apps andam juntos, sprint a sprint. Os **12 primeiros** estão com os
**Sprints 1, 2 e 3** feitos; `cin-segunda-via` e `metas-bi-ocr` já têm o **Sprint
4 parcial**. Os **8 novos** (`custodia-definitiva`, `trilha-custodia-necropsia`,
passivo, renovação, DOCUMENTAPOLITEC, Gestão de Documentos, Controle de
Aquisições e Distribuição de Casos de DNA) estão com os **Sprints 1, 2 e 3**.
Todos têm a parte técnica do Sprint 0 (dados fictícios, bibliotecas, modelos). Os
itens do Sprint 0 que dependem de pessoas (autorizações, amostras reais, linha
de base) continuam abertos no `sprint.md` de cada app.

Em 30/10/2026 os 20 apps ganharam a **identidade visual SESP/MT e POLITEC/MT**,
com personalização por app, tema claro como padrão e ajuste do tamanho da fonte
(ver [IDENTIDADE-VISUAL.md](IDENTIDADE-VISUAL.md)). No mesmo dia, o Sprint 3 dos
6 apps novos foi feito.

Os 77 itens do Sprint 0 que dependiam de decisão institucional, documento
oficial ou medição do processo real foram **elucubrados**: cada um tem um valor
plausível, documentado em [PREMISSAS.md](PREMISSAS.md), com o nível de
confiança e o que precisa ser confirmado com quem responde pelo processo. As
referências que faltavam (modelos de DFD, ETP, TR, TAP, ata, laudo, caixa,
marcos, plano de trabalho, esquema do Hórus) foram criadas nas pastas
`modelos/` e `horus/` dos apps. Nenhum item bloqueia o desenvolvimento.

Duas premissas deixaram de ser elucubração, porque a norma foi consultada no
acervo [ctresb/leis](https://github.com/ctresb/leis): as categorias da Comissão
de Ética citam o artigo e o trecho real da **LC nº 112/2002-MT** (Código de
Ética Funcional do Servidor Público Civil do Estado) e o fluxo de aquisições
está ancorado na **Lei nº 14.133/2021**. O que continua sendo estimativa são os
prazos em dias e a divisão em etapas.

## Conteúdo de cada pasta

| Arquivo | O que é |
|---|---|
| `README.md` | Ficha do grupo: projeto, contato, fonte e pendências |
| `PROJETO.md` | Especificação completada, gerada pelo formulário a partir do `projeto.json` (problema, MVP, papéis, dados, regras, KPIs, stack, LGPD) |
| `contexto.md` | Contexto completo e arquitetura do app (HTML monolítico, offline first) |
| `sprint.md` | Sprints da construção, do início ao MVP pronto, com a seção **Andamento** |
| `projeto.json` | Resposta **completada pelo professor** (importável no formulário) |
| `envio-original.json` / `projeto-firestore.json` | Resposta original do aluno, sem alteração |
| `app.json` | Título, banco (stores), perfis, rotas, bibliotecas e dados embutidos do app |
| `src/app.js` e `src/sprintN.js` | Código do app: o `app.js` traz os Sprints 1 e 2; cada sprint seguinte ganha o seu arquivo |
| `index.html` | O app pronto (gerado pelo `construir.py`; não edite direto) |
| `exemplos/` | Gerador e dados fictícios com semente fixa |
| `vendor/` | Bibliotecas de terceiros com versão e SHA-256 em `VERSOES.md` |

Todos os apps seguem a mesma arquitetura: **um único `index.html`** (CSS, JS,
bibliotecas e dados de base embutidos), que abre com duplo clique no Edge ou no
Chrome, guarda os dados no IndexedDB e funciona sem internet.

A exceção é o **agendamento-cin**: a agenda pública precisa de uma fonte única
de vagas. O `index.html` é servido pelo Google Apps Script, a reserva exige
internet, e o painel do posto funciona offline (ver o `contexto.md` dele).

Ao chegar um grupo novo, crie `Apps/<slug-do-projeto>/` com os mesmos arquivos.

## Ferramentas comuns (`_base/`)

| Arquivo | O que faz |
|---|---|
| `PREMISSAS.md` | As premissas assumidas em cada item do Sprint 0 que dependia de pessoas: o valor adotado, onde ele aparece no app, o nível de confiança (A, B ou C) e o que confirmar |
| `CONTINUAR.md` | O que já foi feito em cada app e o que é o próximo passo, para outra IA continuar |
| `IDENTIDADE-VISUAL.md` | O kit visual: paleta, cores e emblemas dos 20 apps, componentes prontos e regras de uso |
| `_base/base.html` | Base de todos os apps: tema claro e escuro, roteador por hash, IndexedDB, perfis da cópia, backup `.json`, carga dos dados fictícios e a tela `#/testes` |
| `_base/construir.py` | Gera o `index.html` de cada app a partir de `_base/base.html`, `_base/js_comum.js`, `<app>/app.json` (rotas, banco, perfis) e `<app>/src/*.js` (o `app.js` primeiro, depois os `sprintN.js`). **Edite as fontes, não o `index.html`** |
| `_base/js_comum.js` | Tela de configuração e testes comuns a todos os apps |
| `_base/embutir.py` | Copia `vendor/*.js` e os JSON de dados para dentro do `index.html`, entre os marcadores `<!-- LIB:... -->` e `<!-- DADOS:... -->`. Substitui o `embutir_libs.py` citado nos `contexto.md` |
| `_base/testar.py` | Abre cada app no Chromium e confere: zero requisição de rede, `#/testes` 100%, todas as rotas, dados fictícios, persistência e tema |
| `_base/testar_sprints.py` | Um cenário de interface por sprint e por app: usa a tela como uma pessoa usaria e confere o "Pronto quando" do `sprint.md`. Os cenários do Sprint 2 estão no próprio arquivo; os dos Sprints 3 e 4, em `_base/cenarios/sprintN.py` |
| `_base/equipes.py` | Grava o login do GitHub de um aluno em `equipes.json` e refaz a tabela "Equipes e GitHub" deste README |
| `_base/painel.py` | Gera `Apps/painel.html`, o painel de desenvolvimento: telas prontas x pendentes por sprint, itens abertos, GitHub e trabalhos de BI |
| `_base/base.html` (utilitários) | Dinheiro em centavos, leitura de CSV, CPF e CNPJ, datas, redução de imagem, campos de formulário: usados por vários apps |

```powershell
python Apps/_base/construir.py                # gera todos os index.html (ou: construir.py <app>)
python Apps/_base/testar.py                   # estrutura dos apps
python Apps/_base/testar_sprints.py           # cenários de cada sprint
node Apps/agendamento-cin/testes/testar_code_gs.js   # servidor do agendamento (Apps Script)
```

Cada app tem um gerador de dados fictícios com semente fixa (`exemplos/gerar_exemplos.py`
ou, no agendamento, `planilha-modelo/gerar_planilha.py`).
